# 轨迹引擎动态避障

`navigation_engine=trajectory`、`allow_bypass=true` 时，新增后台绕行规划。静态障碍保持在场时可以生成替代路线，继续完成有序八字并返回；输入失效、静态停车包络被占用或没有可执行通道时仍停车；移动障碍会继续侵入停车位置时，允许经过完整检查的有限主动脱离。该功能处于验收候选阶段，现有配置默认关闭。

高速近时横穿仍存在已知限制：移动障碍可能侵入急停滑行尾段或已经停稳的位置，当前有限候选不保证每次都能找到可认证的主动脱离。此时仍保持原始点云保护和零速，禁止执行未通过检查的候选。相关接触保留为失败记录，区分急停中与完全停稳后被撞，不计作无碰撞通过；常规快跑、挡停恢复和可行绕行分别验收。

雷达原始点直接进入最终防撞保护。规划链在同一运动补偿结果上保留支持点数，压缩、过滤静态地图背景、聚类并做带衰减加速度的卡尔曼跟踪。首次观测即参与检查，后续观测估速，短遮挡保留预测占用。运动状态使用导数误差与实际位移；源时间上的持续位移超过测量噪声后，即使估速尚未完全收敛，也保留潜在运动占用；低可信状态仍保留微小速度的恒速外推，以及时响应起动，但不外推低可信加速度。轮廓逐帧显露时，根据上一帧的可见边和扩展量调整几何中心，避免将朝向雷达的真实平移扣成轮廓扩展，也避免小幅显露积累成虚假运动。已知轮廓的远边逐渐不可见时，从传感器侧可见边恢复中心；可见宽度大于一半时同样处理，避免把远离雷达的真实平移误估成静止。观测包围轮廓与车辆圆包络分别计算，不把方形目标统一扩大成外接圆。

目标状态含位置、速度及短时衰减加速度。最近关联正常且检测到加速趋势时才向未来传播加速度及其协方差，其余使用恒速预测，保留位置和速度误差；避免未观测的加速度噪声扩展成数米占用。加速趋势的检测门槛为 0.4 m/s² 与半个估计标准差中的较大值，属于待现场核对的模型假设。衰减常数 0.4 s 和过程噪声属于动态目标假设，不能称为实测底盘参数；其作用是覆盖静止目标突然起步，避免恒速预测在启动时持续落后。正常巡航和替代路线均检查实际响应及完整停车尾段。预测默认覆盖 2 s，并检查对应停车尾段；停稳车体保持占用直到整个预测窗口结束，防止随后横穿的障碍撞向停车位置。

自运动补偿不会把移动目标的旧测量变成当前测量；滤波器使用实际点内源时间及延迟观测矩阵。移动模型短暂保持，避免单帧估速靠近零时立即撤掉预测余量、反复加减速。几何搜索使用当前轮廓与定位误差，速度预测误差在带时间轨迹上统一计算。基础误差余量是这份误差预算的下限，预测仅补足超出部分，避免重复膨胀。

后台进程最多处理一个请求和一个最新待处理请求。规划结果在后台完整接收和解码，控制回调只取已经完成的数据；管道刚可读时可能只有半帧，不能在控制回调直接调用跨进程队列的 `get_nowait()`。被覆盖任务中最近 0.6 s 的观测仍按源时间用于跟踪更新，只有最新任务运行几何搜索，更新开销计入同一求解预算。候选限定在当前和相邻有序阶段，对障碍两侧及三个后方接回位置搜索；下一段末端的共享交叉点被占用时，联合迁移该衔接点，并只扩展到其后继阶段接回，停车位不迁移；预算内先搜索静态地图净空较大的一侧，A* 继续考虑净空；有效候选仍按预计完成时间排序。曲线平滑后重新检查地图、原任务走廊、绕数、动态碰撞和实际控制响应。候选速度只修改冲突与接回区间，完成时间评分覆盖剩余任务，移动目标同时比较沿线减速。当前通道仍有效时，换边需达到收益门槛。新路线接受后直接进入最新保护检查；原路线恢复采用两份不同观测连续可行，避免统一长等待和单帧反复启停。慢速短预测无冲突、但恢复正常速度受阻时，仍会提前搜索更快绕路，并继续执行已验证的慢速轨迹；不会因短预测变短而长期只爬行等障碍。

有远期冲突但尚无有效替代路线时，可继续执行检查过的 0.3 秒近期轨迹及其完整停车尾段；检查时限过期则停车，不因后台正在计算就固定停稳。80 ms 是结果接收预算，超时结果丢弃，不能把 Python 数值求解描述为硬实时抢占。静态轮廓侵入初始制动后路时，直接报告 `BRAKING_ENVELOPE_CONFLICT`。移动预测使停车位置不安全时，可选择 `ESCAPE_READY` 或合法绕行候选：从预测切换时刻连接当前运动状态，检查全部有效响应模型的实际运动、完整静态制动扫掠以及动态碰撞，并在首次接受后不超过 0.8 s 恢复完整安全停车后路。重规划沿用首次期限，不续期；期限落在两个预测采样间时，从前一个采样就要求安全停车后路，无法恢复则不接受该候选。关联未通过创新检验，或速度未超过自身两倍标准差时，同时保留原位置不动的轮廓假设；有限脱离的全部实际轨迹仍检查移动预测和静止假设，静止轮廓对应的制动后路全程保留。不能仅凭不可信速度把静态占用抹掉。切换时按实际时间重新检查剩余预测轨迹和最新原始观测，诊断区分候选与 `escape_accepted`。原始点云保护、取消和输入失效停车始终优先；有限脱离期间，取消后的停车本身仍可能受到移动目标侵入。合法反向尖接点将参考速度降至零，保持有限速度边界。终点回零使用相同的有限驱动力停车尾段预测，并保留当前位姿已进入停车容差的条件；预测落点预留已有共享误差余量，最终到位仍使用原停车容差，不重复扣除余量。

新轨迹保留非零边界状态，预测采用实际定位更新周期。立即停车从当前补偿位置起算；响应预测从当前补偿位置开始，保留计算与控制接收期间的旧路线运动，再在 100 ms 的切换边界接入新路线；停车状态在接入前保持原零速。保护层反馈带源时间的最终输出，最近 0.5 s 指令用于各响应模型的实际延迟队列，避免刚回零就把尚未生效的旧非零指令抹掉。有序投影仍限制在物理可达窗口。执行时再次检查当前位置、最新观测及障碍预测，只接收同一运行和路线来源的有效结果。最新原始点按同一制动距离和实际滑行前缀检查，完整两秒轨迹由带时间障碍预测检查，避免将已移动目标的旧轮廓作为整个未来轨迹的静态否决。仅速度变化时保留当前有序进度；新几何路线从已验证的运动边界接续，避免折返附近重匹配到后续支路。原任务阶段进度与替代轨迹弧长分别记录；原入场通道改变后，返回以实际入场路线逆序为基准。返回及下瓣退出衔接的再次规划使用已完成的入场走廊，对仍有净空的既有绕障通道保留绕侧关系；新障碍直接占据参考路线时仍允许重新选路。桥接中的衔接点沿原检查点位置按顺序匹配，避免额外绕行长度把阶段边界推到下一瓣。停车位和已完成阶段不迁移。

`mission/trajectory` 原子包含指令、运行/路线身份、定位源时间和近期路径。新引擎的保护层仅执行该快照中的指令；原 Twist 保留诊断。控制器为 40 Hz，最终保护检查为 100 Hz，雷达处理仍按真实观测频率运行。取消和运动禁止始终优先。状态和完整展示路径由独立诊断进程发布，保留原话题及 QoS，每种话题只保留最新待发快照；完整任务历史仍在状态快照内。控制指令、使能和原子速度快照继续直接发送。这样可隔离可靠 DDS 订阅端回压；[Humble 的发布实现](https://github.com/ros2/rclpy/blob/humble/rclpy/src/rclpy/publisher.cpp)在原生发布调用期间持有 Python 锁，仅换成同进程线程不能隔离这种等待。

## 验证入口

所有输出使用新的项目内 `artifacts/` 子目录，原始地图和 bag 只读。

```bash
scripts/verify-avoidance.sh --suite model --output artifacts/avoidance-model
scripts/verify-avoidance.sh --suite replay --output artifacts/avoidance-replay
scripts/verify-avoidance.sh --suite gazebo --output artifacts/avoidance-gazebo
scripts/verify-avoidance.sh --suite all --output artifacts/avoidance-all
```

`model` 默认运行 300 个固定种子的几何及响应模型场景；`gazebo` 默认运行 60 次场景及进程停更/模拟断链检查。`--cases` 和 `--case-offset` 用于明确标记的开发子集，低速物理矩阵使用 `--speed-scale 0.5|0.75|1`，不连续子集可用 `--case-indices` 在同一传感器会话中运行，不能与 `--cases` 或 `--case-offset` 混用。每场保存途中停车、低于 0.2 的时长、实测换路速度与整圈用时；不将起步及末端停车确认时间算作途中失速。无障碍增量耗时对照使用同一力驱动、传感器定位和串口链：

```bash
scripts/verify-avoidance.sh --suite gazebo --baseline --cases 10 --output artifacts/avoidance-off
scripts/verify-avoidance.sh --suite gazebo --cases 10 --output artifacts/avoidance-on
scripts/verify-avoidance.sh --suite gazebo --cases 1 --case-offset 12 --gui --output artifacts/avoidance-gui
```

物理场景使用自有 `intramural_sim` Fortress 插件，由延迟指令、实测有效响应和驱动力上限生成力，让刚体引擎积分；保持原模型碰撞与传感器。固定轮组和简化接触仍是仿真假设。只有显式提供 `drive_acceleration_limit` 的仿真配置使用相应制动包络，实车不得用命令加速度冒充测得的制动力。验收器用真值检查实际净空、绕数和停车，不把真值交给传感器定位。

传感器桥沿用已安装 `ros_gz_bridge` 的转换，退出时解除桥端点和定时器，等待在途传输释放 ROS 节点引用后再关闭上下文，避免节点销毁晚于 DDS 全局清理。生命周期检查包含 C++ 回归及真实大点云传输中的 SIGINT、SIGTERM 退出。

动态演员也由有限力驱动，其加速度、响应时间和惯量旋转阻尼是场景假设。演员接收世界坐标速度，车辆仍接收车体坐标速度；独立净空检查使用演员实际朝向，并覆盖采样之间的平移及旋转。先运行独立无障碍圈建立演员绝对时序，后续演员不根据避让后的车辆位置追车；另用该固定时序与无避让参考检查是否确实形成交会冲突。提前让行后实际距离较远仍可有效，缺乏交会的场景不会计为动态通过。

重放分两层：录制位姿用于组件级时间补偿与目标跟踪；原始 Livox/IMU 在隔离图中以 1× 运行 Point-LIO、小型配准、正式保护层观测与同一个后台规划器，模拟串口始终零速，禁止同时注入录制 TF/里程计。原始链使用在线定位 TF，记录位姿仅供组件级重放；其坐标变换与正式定位链一致。影子参考按录制时间索引单个 RETURN 几何，不能冒充历史十阶段进度；历史主动指令未记录时，仅在预测中以在线估计速度近似，输出快照指令保持零。历史观测不会随新路径改变，因此重放不能证明车辆沿反事实路线完成绕行。重放结果中的通过表示链路、时序和零速传输检查通过；实验地图中的未测量任务几何、单段参考和缺失的历史指令限制了影子决策的解释范围，不能据此宣称完整任务无误停。影子冲突及拒绝结果同样保留。人工移动的仿真目标和几何压力场景另行标记。

每轮记录源码、配置、输入身份、命令、退出码、轨迹、净空和耗时。功能结果与计算耗时分别判定，失败记录保留。入返通道使用独立真值检查；原返回通道实际被障碍占据时，允许配置范围内的局部绕行，并保留历史入场绕侧检查。跟踪误差和绕行范围分别计入，不把允许的路线变化判作跟踪失败。静态检查、模型、重放、物理仿真和实车验收分别解释。

## 配置与现场边界

`allow_bypass=false` 保持原挡停、清障后恢复。已有冻结地图配置不自动修改；显式启用时，使用 `srm-nav field MAP_DIR --allow-bypass --output cache/navigation-bypass` 在新目录重新生成；关闭使用 `--no-bypass`，原地图和配置保持不变。仍使用现有 `srm-nav` 连接、定位、待机、显式 drive/start、cancel/reset 流程；不要直接改带哈希的 `arena.json` 后继续使用旧缓存路线。

诊断查看 `mission/status` 中的 `behavior`、`obstacle_version`、`route_id`、`original_progress`、`bypass_count` 和 `avoidance`；后者含求解时间、速度倍率、接回位置和拒绝原因。被接受的替代路线保存为运行目录中的 `route-<id>.json`。关闭开关并重新生成配置可回到挡停行为；基线恢复以冻结版本和对应个人地图配置为准。

目前已有低速有效响应与停车日志，完整的高速、正反向及侧向无遮挡制动样本仍需现场补采。使用 `scripts/measure-response.sh plan --axis both --levels 0.5 1.0 1.5 2.0 --repeats 2 --seconds 0.8` 先检查采集序列；真正执行仍需现有车辆限幅、操作者和停机条件。计划上限沿用当前 candidate；录制仍受个人车辆限幅和原 1.5 米调试区域约束，不会修改车辆限幅。软件验收不能代替 NUC 性能测量和现场静态、动态绕行验收。

搜索代价参考 [Nav2 Smac 2D 的净空代价设计](https://api.nav2.org/nav2-humble/html/smac__planner__2d_8cpp_source.html)，在项目已有 A* 中实现；力驱动使用 Fortress 的 [ExternalWorldWrenchCmd 世界坐标力接口](https://gazebosim.org/api/gazebo/6/gz_2sim_2components_2ExternalWorldWrenchCmd_8hh.html)。本轮保留现有控制器和最终速度所有权。
