# 底盘响应测量与旧日志复用

先利用已有实车记录，只补缺失量。方向、比赛 19 字节协议、现场已确认的断链停机与整圈完成无需重新验证。速度和距离以下均沿用车载激光定位的米制尺度，不需要卷尺或相机；它们不是独立外部基准的绝对精度标定。

## 当前参数来自哪里

| 参数 | 当前实现 | 来源与含义 |
|---|---|---|
| 发送频率 | 100 Hz | 比赛接口与已有实车 TX 记录；不是底盘响应频率 |
| 速度换算 | 1:1 初值 | 现场批准；+x 前进、+y 左移已确认，绝对尺度没有独立测量 |
| `response_delay` | 0.2 s | 原软件假设；保留给碰撞扫掠与标称离线底盘模型 |
| `tracking_prediction_delay` | candidate 为 0.09 s；未设置时继承 `response_delay` | 跟踪提前量，另加定位时间戳年龄；与防撞延迟分开。0.09 来自旧有效响应模型延迟项约 0.077–0.092 s 的对照试验初值，仍需本次实车确认 |
| `response_tau` | 离线默认 0.15 s | 模拟底盘一阶时间常数；当前前馈跟踪器没有使用该参数建模一阶底盘 |
| 速度估计滤波 | 0.15 s | `OmniTracker.observe` 的软件滤波尺度，不能当成实测底盘 τ |
| `braking_acceleration` | 0.2 m/s² | 软件制动估计，不能当成已实测的机械制动能力 |
| `terminal_deceleration` | candidate 为 1.0 m/s² | 正常停车的规划减速度，受 `max_acceleration` 限制；提前量为跟踪预测延迟加一次定位周期。与防撞制动估计分开，未配置的旧方案不变 |
| 压力场景 | 延迟 0.4 s、τ=0.3 s | 人工构造的压力测试，不是实车测得的范围 |

## 已从旧实车记录获得的量

2026-10-16 的有效点动记录包含 440 帧发送及 436 个有效回包：发送间隔中位数 **9.984 ms**、最大 **10.824 ms**。回包不含“这条速度何时被执行”的确认，不能用它计算机械响应时间。

18.554 秒基线记录的 TF 年龄中位数 **30.6 ms**，最大 **129.5 ms**；另一轮低速记录为 **40.7 / 92.0 ms**。这些是定位时间戳年龄，不能等同于执行延迟。

旧监控记录保留最终 `cmd_vel` 接收时间、任务起始时间、任务经过时间、TF 年龄和位置。依据旧代码中同一 tick 的时间语义，用 `任务起始时间 + 经过时间 − TF 年龄` 重建位置源时间，按位置积分模型拟合，并把末尾 30% 时间留出验证。任务结束后经过时间已冻结，改用接收时间减 TF 年龄近似；不把缓存的 guard 事件当成新位姿：

| 记录 | 拟合延迟 / τ | 留出位置 RMSE | 解释 |
|---|---:|---:|---|
| 18.554 秒基线 | 0.105 / 0.008 s | 2.77 cm | 综合滞后约 0.113 s；两参数相关性高，不能分别确认 |
| 低速整圈 | 0.066 / 0.045 s | 1.91 cm | 综合滞后约 0.111 s；两参数仍难分开 |
| 切入记录 | 0.092 / 0.089 s | 1.98 cm | 本段可辨识的有效模型，允许用于离线对照 |
| 人挡停记录 | 0.090 / 0.030 s | 1.32 cm | 可复用的有效响应模型 |
| 较早整圈记录 | 0.077 / 0.052 s | 1.79 cm | 可复用的有效响应模型 |
| 高速失效记录 | 0.070 / 0.055 s | 11.62 cm | 固定线性模型预测较差，不用作替换参数 |

这是对已有实车数据的辨识结果，不安排重测这些已有量。源时间由旧状态字段重建，输入是最终话题而非串口写入；所得模型包含下游执行链的影响，不能精确拆分 MCU、机械与定位误差。综合滞后及适用范围可以复用，不将无法分辨的参数强行写成精确标定值。

拟合输出保留源文件 SHA256、时钟口径、训练/留出误差和参数相关性。`eligible_for_model` 仅表示该数据段足以支持此低阶模型；不代表跨速度、电池和地面均有效。`gain_world_from_input` 含当时车头在地图中的旋转，**不能直接复制为 `body_to_protocol`**。

## 命令与流水步骤

在当前开发分支项目根目录执行。WSL 使用项目容器；NUC 已有 Humble 时设置 `export INTRAMURAL_NATIVE=1`。新目录不会覆盖旧结果，所有采样默认留在本地 `artifacts/response/`。

先处理旧记录，无需车辆：

```bash
scripts/measure-response.sh fit \
  --trace artifacts/your-field-run/trace.jsonl \
  --output artifacts/response/history-source
```

同一文件加 `--clock receipt` 可对照端到端观测延迟。默认 `source` 拟合不包含已知的定位年龄；`receipt` 包含定位及聚合等待，不可再与 TF 年龄叠加后当成机械延迟。

`response-model.json` 汇总结果，`model-N.json` 保存单段模型，`prediction-N.json` 保存预测位置。`stopping_samples` 从已有“非零→持续零速”片段提取停车前速度、零速到确认静止的时间和最大位移；不完整尾段会跳过。等效减速度包含延迟，故不会直接覆盖独立的 `braking_acceleration`。

只有剩余参数确实缺少可用数据时，执行一次地面流水。先在 NUC 停止 `drive`、旧哨兵通信及其他串口发送者；保留单套传感器。车辆落地，平整区域内确保前后左右各有约 1.5 m 空地，现场能立即切断电机动力。这个工具不具备导航避障，不能在桩旁或有人穿行时使用。不要用架空轮子测地面动力学。

终端 A 启动现有传感器；已在运行时复用，不重复启动：

```bash
srm-nav sensors
```

终端 B 先查看流水计划，不打开串口、不发送指令：

```bash
scripts/measure-response.sh plan
```

旧日志已覆盖约 0.27、0.33、0.48 m/s 的三次停车：回零后最大定位位移约 2.2、3.7、5.2 cm；到确认静止分别约 0.42、0.46、0.83 s，包含静止确认窗口。这些记录直接复用，不重录相同低速档；其等效减速度约 1.5–2.2 m/s²，含延迟、速度估计窗口与定位误差，不写成机械制动能力。

默认只补 x/y 两轴、±0.6 指令、两轮；每段 2 s，之后零速记录 2 s，总计约 35 s。需在个人车辆已批准的限幅内运行，脚本不会提高该限幅。序列正负成对，预计接近原位，但不是闭环自动回位。各阶段沿用个人底盘配置的轴映射、加速度和限幅，拟合输入使用实际发送值。只缺单轴时用 `--axis x` 或 `--axis y`；后续确需补更高范围时显式指定 `--levels 0.6 0.9`，先看计划与空地条件。指令会爬升，不能把请求幅值当成实际达到的速度。

确认现场条件后，由操作者执行：

```bash
export INTRAMURAL_NATIVE=1
scripts/measure-response.sh record \
  --vehicle-config cache/vehicle-current \
  --execute --stop-available
```

默认选择唯一匹配的 USB 串口，必要时用 `--device /dev/serial/by-id/...` 指定。复用导航锁和串口独占锁；跨用户旧程序须现场先退出，锁不能代替协调。`Ctrl-C`、定位停更、时钟异常、串口超时和超出采样区域会回零并关闭串口，已采数据保留。物理断线后仍依靠已确认的下位机或硬件停机机制。

输出逐帧写入时间、写入完成时间、ROS 时间、里程计源/接收时间和位姿；默认里程计为 `/intramural_robot/aft_mapped_to_init`。完成后自动拟合并生成 `fit/`。定位源时间和 NUC ROS 时间需共钟；报告中源时间模型描述执行链，接收时间模型描述操作者实际可观测的总响应。

## 拟合、采纳与后续测试

模型为 `dv/dt = (K·u(t−d)−v)/τ`，对位置积分后拟合，避免直接微分放大 10 Hz 位姿噪声。模型使用前 70% 时间辨识，后 30% 做预测验证；参数落边界、强相关、激励不足或验证误差过大时不标为可用。停车统计与响应辨识分开。

新数据可以替换同一口径的旧假设，保留来源与速度范围。例如把合格的 `model-N.json` 传给[离线对照](../architecture/controller-comparison.md)，它会同时更新模拟响应和 MPPI 的响应模型。未测得的制动能力仍保留原值；不能从低速停车外推高速制动。现有程序不会自动修改车辆配置、放行标志、速度倍率或运行档位。

下次实车只做：检查本次硬件/固件是否改变 → 复用已有数据选档 → 必要时补这一次响应流水 → 跑一轮新算法完整路线。旧方向、协议、已确认停机和历史成绩不重复验收。新控制算法及其挡停恢复仍需实车检查，因为旧版本通过不能替代新版本效果。
