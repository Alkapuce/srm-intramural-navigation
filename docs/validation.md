验证环境为 WSL2、Ubuntu 22.04 / ROS 2 Humble 容器、Ignition Fortress 和 NVIDIA D3D12。以下为 2026-10-12 至 2026-10-13 完成的实际记录，使用赛方提供的圆柱哨兵 Xacro、公开传感器资源、解析场地先验和模拟串口；实车及 NUC 硬件未验收。

## 调试中定位并修复的问题

| 问题 | 原因与修复 | 验证 |
|---|---|---|
| 大点云传输丢帧 | 约 1 MB 点云超过旧共享内存消息上限；配置 32 MiB 段与 2 MiB 单消息上限，UDP 限定回环地址 | 实际 12 秒收帧对照恢复至 20 Hz；普通话题 QoS 保持 |
| 生成后重力方向错误 | 短暂失重被用于 Point-LIO 初始化；仿真适配器等待 IMU 连续稳定 0.5 s 后送入扫描 | 静止位姿与完整传感器路线；真实驱动不使用此仿真适配器 |
| 安装变换尚未取得时输出错误点云 | LOAM 安装矩阵初始化和 TF 到达顺序问题；取得有效安装 TF 前暂停转换 | 实际 C++ 节点与 ROS 消息回归，已知点变换结果正确 |
| 底盘里程计依赖点云同步 | 里程计回调被额外点云配对延迟；独立发布并保留输入时间戳 | 实际 C++ 节点在没有点云时仍输出正确里程计 |
| 大消息转换中退出异常 | 默认 ROS 信号可能在原生消息转换中释放上下文；回调完成后统一清理 | SIGINT/SIGTERM 大消息回归，正常零速与释放 |
| 入口绕行后返回走到障碍另一侧 | 末尾衔接仍使用原始入口；保存实际入场路径并逆序返回 | 独立真值轨迹审计，四处绕行返回偏差 0.0374–0.0803 m |

## 证据边界

轮组采用固定关节和理想平面速度驱动，没有实车滑移、制动和电机环模型。模型粗略圆柱包含参考雷达扫描原点，GPU 光学层单独排除本车粗略外观；GUI 外观、惯性和全部碰撞保留。车体包络、安装初值与具体假设见[任务说明](arena-mission.md)。

模拟下位机保持无超时停车：物理链路断开后，上位机取消并发零速，模拟底盘仍可保持末帧约 0.1721 m/s，观察窗口内移动 0.0620 m，恢复链路后才停下。接车前必须确认下位机断链停车或经测试的等效硬件停机机制，不能把上位机看门狗当成断线后的物理停车保证。

历史一次 `terrain_analysis_ext` 原生退出崩溃尚未独立归因。当前完整矩阵、20 次 Release 与 20 次 ASAN 压力运行未复现，不能据此声称永久消除。异目录原生入口测试在 Humble 容器内执行，不代表真实 NUC 图形或设备已经通过。

当前代码的重复构建和运行入口见[README](../README.md)与[脚本索引](../scripts/README.md)。需要展示效果时先检查定位就绪，再启动任务；实车调试按[接车验证流程](prevehicle-candidate.md)进行。

## 2026-10-14 干净交付克隆复验

从只含对外交付内容的 `main` 新建独立克隆，递归获取 9 个顶层依赖及 pb2025 的 7 个子模块，再应用 3 个完整补丁。克隆没有旧开发历史、内部计划或 Agent 约定，也没有预先存在的工作空间安装；使用已有 Humble 镜像执行实际复现入口。

首次调用暴露旧脚本先检查安装包、后构建的顺序错误。修复后完整运行通过：31 包独立构建、当前 60 项测试、传感器定位与串口模拟一圈、运动中取消、复位及正常退出，回位误差 **0.0351 m**。[复验结果](results/2026-10-14/reproduction.json)记录被测代码版本及实际数值。新增测试通过真实 CLI 覆盖普通克隆留下空子模块目录的恢复、重复准备和额外文件保护；旧行为下该场景失败。

本轮验证源码交付与恢复路径，没有重新构建未改动的容器镜像，也没有连接 NUC 或实车。前述 2026-10-13 五圈及障碍矩阵的 59 项测试记录保留原数值，本轮新增回归后的 60 项测试另行记录。
